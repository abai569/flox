SDWAN 组网与规则使用教程

这份教程专门解决两个问题：第一，怎么把节点真正组进同一张网；第二，组网完成后，规则页面里的「转发模式」应该怎么配、和组网是什么关系。

先说结论

一、组网 和 转发模式 的关系

很多人会把「组网」和「规则」混在一起理解，其实它们是两层东西：

组网

作用是让多个节点先加入同一张虚拟网络，拿到各自的 VPN IP，知道谁是主中心节点、谁是备用中心节点。 这是节点与节点之间的通信基础。

规则里的转发模式

作用是决定这条具体的转发规则到底走哪种转发内核，比如 `gost`、`nftables`、`floxcore`、`sdwan`。 这是业务流量怎么转发。

你可以把它理解成：先组网，再决定规则要不要使用这张网。
组网是「地基」，`mode=sdwan` 是「这条规则是否踩在这块地基上运行」。
一句话理解

二、最简单的使用思路

  • 如果你只是想让节点加入同一张虚拟网，先去「组网」页面做批量组网。
  • 如果你想让某条转发规则通过这张虚拟网来转发，再去「规则」页面把这条规则的 转发模式 选成 sdwan。
  • 如果规则还是选 gost 或 nftables，那它就不会走 SDWAN 这张虚拟网。
使用顺序

三、正确的操作流程

  1. 先到「组网」页面，完成节点入网

    在左侧菜单点击 组网，这里是全局 SDWAN 管理页面，不是某一条规则的配置页面。

  2. 设置全局网络参数

    在「全局网络配置」卡片里设置：

    • SDWAN 网段，例如 192.168.100.0/24
    • 自动故障切换 是否开启
    • 故障切换检查间隔

  3. 选择要加入网络的节点，点击「批量组网」

    这一步会自动完成：

    • 生成 CA（首次）
    • 选定主中心节点
    • 给节点签发证书
    • 给节点分配 VPN IP
    • 下发中心节点信息

  4. 确认哪些节点已经入网

    在「当前网络成员」区域里，你可以直接看到：

    • 哪些节点已经入网
    • 每个节点的 VPN IP
    • 谁是主中心节点
    • 谁是备用中心节点
    • 哪些节点还未入网

  5. 然后再去「规则」页面创建或编辑转发规则

    这时你才开始配置业务规则。这里的重点是看 转发模式。

  6. 把需要走虚拟网的规则，转发模式设为 sdwan

    只有这一步做了，规则才会真正调用 SDWAN runtime。

最重要

四、规则页面里的「转发模式」到底怎么选

模式 适合场景 和组网的关系
gost 通用转发，走传统用户态路径 即使节点已经组网，这条规则也不会用 SDWAN 网络
nftables 性能优先，纯 DNAT 转发 即使节点已经组网，这条规则也不会用 SDWAN 网络
floxcore 自研转发内核 和 SDWAN 无直接关系，是另一条独立内核路径
sdwan 希望这条规则通过 SDWAN 虚拟网转发 只有它会真正用到你前面组好的这张网
组网完成之后，不是所有规则都会自动走 SDWAN。
只有你在规则里明确把 转发模式 选成 sdwan，它才会走这条链路。
如果这条规则绑定的是链式隧道，系统会自动按隧道里定义的入口节点 / 中间节点 / 出口节点角色转发，最后由出口节点去连接真正的落地地址。
实际例子

五、典型使用场景

场景 1：两台节点先组网，但规则仍走 gost

  • 节点 A 和节点 B 已经在「组网」页面入网成功
  • 你在「规则」页面创建一条规则，模式选的是 gost
结果：这条规则不会使用 SDWAN 网络。
节点虽然已经在同一张网里，但这条规则依然走 gost 自己的路径。

场景 2：两台节点先组网，规则模式选 sdwan

  • 节点 A 和节点 B 已经入网
  • 你在「规则」页面把某条规则的模式改成 sdwan
结果：这条规则会调用 SDWAN runtime，节点之间的转发链路会优先使用 Nebula overlay。

场景 3：链式隧道里已经定义了入口 / 中间 / 出口节点

  • 例如隧道里已经定义：sh -> hk -> jp
  • 规则绑定这个隧道
  • 规则模式选 sdwan
  • 落地地址填写最终公网目标，例如 us:443
结果：系统会自动按隧道角色展开转发链路：
sh -> hk -> jp -> us
其中 us 不需要加入组网，最终由出口节点 jp 去连接它。

场景 4：还没组网就直接把规则模式设成 sdwan

  • 节点没有签发证书
  • 节点没有 VPN IP
  • 没有主中心节点
结果：规则会失败或无法正常建立 SDWAN 通道。
所以必须先组网，再用 mode=sdwan。
建议做法

六、推荐的实际配置方式

推荐做法

  1. 先把所有候选节点在「组网」页面批量入网
  2. 确认「当前网络成员」里都能看到它们的 VPN IP
  3. 确认主中心节点和备用中心节点都在线
  4. 如果是链式隧道，先在隧道里把入口 / 中间 / 出口节点定义清楚
  5. 再去「规则」页面，把确实要走组网通道的规则切到 sdwan

不推荐做法

  1. 先建一堆 mode=sdwan 的规则
  2. 之后才慢慢回头给节点签证书、设中心节点、分 VPN IP
这样很容易出现：规则已经创建了，但节点还没真正入网，结果看起来像“规则有了，网络没通”。
排查

七、如果规则用了 sdwan，但还是不通，先看什么

  1. 去「组网」页面确认节点是不是已经属于“当前网络成员”
  2. 确认节点是不是已经有 VPN IP
  3. 确认节点证书是不是“已签发”
  4. 确认主中心节点是否在线
  5. 如果主中心节点离线，点一次「故障切换检查」
  6. 如果绑定的是链式隧道，确认隧道里的入口 / 中间 / 出口节点顺序是否正确
  7. 确认这条规则的转发模式是不是确实已经切到 sdwan
最后总结

八、一句话记住

先组网，再在规则里把需要走虚拟网的规则切成 mode=sdwan。
  • 组网页面解决的是：节点有没有加入同一张网
  • 规则页面的转发模式解决的是：这条流量到底走哪条内核路径
  • mode=sdwan 才是“让这条规则使用组网结果”的开关
  • 如果规则绑定的是链式隧道，那么最终会由隧道里的出口节点去连接落地地址
